## Короткий огляд виконаних завдань

### 1. Логічна схема реляційної моделі (Завдання 1–2)
Логічна схема спроєктована на основі концептуальних класів попереднього завдання (`DB-CW-2`).  
Вона містить 9 реляційних таблиць:
- `Client` (Клієнти)
- `Employee` (Персонал / Співробітники)
- `Supplier` (Постачальники фурнітури)
- `Manufacturer` (Фабрики-виробники)
- `Furniture` (Меблеві вироби)
- `Orders` (Замовлення)
- `OrderItem` (Позиції замовлення — нормалізація зв'язку багато-до-багатьох)
- `Contract` (Договори купівлі-продажу)
- `Receipt` (Розрахункові квитанції)

Повний Mermaid-код та зв'язки подано у файлі [`RelDB.md`](./RelDB.md).

---

### 2. Дерево реляційної алгебри (Завдання 3–4)
Для демонстрації реляційних операцій обрано бізнес-запит:  
> *«Отримати назви меблів (`name`), вартість яких перевищує 15000 грн (`price > 15000`), що були замовлені зі статусом 'виконується' (`execution_status = 'виконується'`)»*.

**Операції реляційної алгебри:**
- **З'єднання 3 таблиць:** `Furniture` $\bowtie$ `OrderItem` $\bowtie$ `Orders`.
- **Вибірка ($\sigma$) для двох таблиць (стовпці не є PK/FK):**
  - $\sigma_{price > 15000}(Furniture)$
  - $\sigma_{execution\_status = 'виконується'}(Orders)$
- **Проекція ($\Pi$):**
  - $\Pi_{name}(t_4)$ — вибір одного стовпця `name` таблиці меблів.

Повний Mermaid-код та схему графа подано у файлі [`RelTree.md`](./RelTree.md).
